# cloud-agent-infra

A cloud-hosted, always-on **Debian box** reached over **Tailscale** from another
device — laptop or any tailnet node: a small Hetzner Cloud VM (CX33, Nuremberg)
running Debian 12, built and managed entirely as code (Terraform + bash), with a
single source of truth for configuration. The infrastructure connects and manages
itself to your tailnet and stays reachable while your local machine is asleep.

This repo is the **infrastructure layer only**: it builds the VM, joins it to the
tailnet, keeps it verified, and gives you hand access to it (SSH, and a browser
on a virtual display you can drive over VNC). It knows nothing about opencode or
the phone — an agent layer that installs those onto this box and wires up phone
approval lives in the sibling repo
[`~/stuff/phone-approval`](../phone-approval).

## Architecture

```
┌─────────────────────────────────────────────────────────────┐
│  Hetzner CX33  "cloud-agent"   (Debian 12, nbg1 Nuremberg)  │
│                                                             │
│   • Debian stable + apt; unattended security updates        │
│   • tailscaled (systemd) -> joins tailnet as "cloud-agent"  │
│   • Tailscale SSH: `ssh <user>@cloud-agent` lands here      │
│   • Xvfb :99 + headed-chromium (CDP, persistent profile)    │
│   • x11vnc, loopback only, started by hand (`./run browser`)│
│   • Persistent data volume mounted at /mnt/data             │
│     (writable root — no COS quirks)                         │
└─────────────────────────────────────────────────────────────┘
          ▲
          │  Tailscale (private tailnet, no public inbound)
          ▼
   Any tailnet device:  ssh <user>@cloud-agent
```

## The one command

```sh
./run up
```

`up` is a **convergence** command, not a build script: every step first asks what
is already true and does nothing if the answer is "already correct". It ends by
running `verify.sh`, so it can't lie to you about the result. It is
**non-destructive by contract**. Repair a broken box with `up`; run `./run` with
no arguments to list everything.

The full command surface, every script, and the flows they compose are mapped in
[`docs/capabilities.md`](docs/capabilities.md); the detail is in
[`docs/operating.md`](docs/operating.md).

## Repository layout

```
cloud-agent-infra/
├── README.md             # this file: the front door
├── SPEC.md               # goals, what exists, open questions
├── TASK.md               # open work
├── run                   # operational entry point — `./run`, `./run rebuild`
│
├── config.env            # SINGLE SOURCE OF TRUTH (git-ignored; holds secrets)
├── example.config.env    # template to copy
├── .gitignore
│
├── terraform/            # one root module per provider — `PROVIDER=` in config.env picks it
│   ├── hetzner/          # ACTIVE: CX33 + volume + firewall (zero public ingress)
│   │   ├── versions.tf / variables.tf / main.tf / firewall.tf
│   │   └── tailscale.auto.tfvars   # GENERATED by mint — one-off auth key (git-ignored)
│   └── gcp/              # GCP path (reference; switch PROVIDER=gcp to use it)
│       ├── versions.tf / variables.tf / compute.tf / network.tf / startup.tf
│       └── .terraform.lock.hcl     # committed: pins the provider version
│
├── scripts/              # everything `./run` dispatches; mapped in docs/capabilities.md
│   ├── lib.sh            # shared: repo-root resolution, config, PROVIDER shim, ssh helpers
│   ├── templates/startup.sh   # shared 2-phase startup (disk-by-label, re-runnable unit)
│   ├── up.sh             # THE command: converge everything to verified, non-destructively
│   ├── bootstrap.sh      # terraform init + mint auth key (GCP path: also GCS backend)
│   ├── cleanup.sh        # tear down compute + state + local files + tailnet node
│   ├── tailscale-api.sh  # mint/validate one-off auth keys, delete stale tailnet nodes
│   ├── rekey.sh          # get a working auth key into an EXISTING box (apply can't)
│   ├── wait-ready.sh     # block until the box is on the tailnet and provisioned
│   ├── verify.sh         # asserts the whole end state; non-zero exit on any drift
│   ├── verify-browser.sh # browser-stack sidecar; verify.sh runs it concurrently
│   └── browser.sh        # `./run browser`: hand-drive the box's browser over VNC
│
└── docs/
    ├── capabilities.md   # command ↔ script ↔ flow map
    ├── operating.md      # the operator's manual
    ├── decisions/        # every settled question + status (see decisions/README.md)
    └── measurements.md   # the evidence those decisions rest on
```

Every script resolves the repo root from its own path and `cd`s there, so they can
be run from anywhere; `run` is a thin, ordered dispatcher over them. Terraform is
never run by `cd`-ing — `scripts/lib.sh` wraps it as `terraform -chdir=terraform`.

## Setup

```sh
cp example.config.env config.env   # then edit the values
./run up
```

From an empty project that does the whole thing: `terraform init` → one-off auth
key → server + volume → wait for first boot → verify. `docs/operating.md` has the
config reference, the prerequisites, and the day-to-day commands (connect,
browser, teardown). Prerequisites: a Hetzner Cloud API token and a Tailscale API
key in `config.env`; `terraform` locally. (The GCP path, if `PROVIDER=gcp`, needs
`gcloud` + application-default credentials instead.)

## Teardown

```sh
./run cleanup                # FULL wipe (server + volume + local state + tailnet node)
./run tf destroy -target=hcloud_server.agent && ./run up   # replace the server, keep data
```
